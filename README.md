# ml_test: how binary classification works, from a line to boosted trees

A hands-on guide. One tiny dataset (500 bank customers: will they default on their
loan?) and three models of increasing complexity, each small enough to read in one
sitting:

1. **logistic regression** (scikit-learn): a weighted sum of the features;
2. **gradient boosting** in its simplest form: a sum of small trees, written from scratch;
3. **XGBoost's math** from the paper (Chen & Guestrin, KDD 2016), written from scratch
   and checked against the real `xgboost` library to about 1e-6.

Every script prints a few numbers. The way to learn is to change a setting, rerun,
and explain to yourself why the numbers moved. Each step below says what to try
and what you should see. All numbers in this README come from running the scripts.

For a reading plan of the XGBoost paper alongside the code, see [HOW_TO.md](HOW_TO.md).

## The data

`bank.py` loads `bank.csv`: 500 customers with two features and one label.

| Column | Meaning |
| --- | --- |
| `income` | annual income, k EUR |
| `missed` | missed payments in the last 12 months (0 to 5) |
| `defaulted` | 1 if the customer defaulted, else 0 (`y` in the code) |

Rows 0-399 are the **training set** (the model learns from them), rows 400-499 the
**test set** (used only to judge it). 43 of the 100 test customers defaulted, so
always answering "no default" already gets **57/100**. That is the bar to beat.

The data is synthetic: generated by a logistic model with a small interaction, from a
fixed seed, then frozen in `bank.csv` so it never changes. Delete `bank.csv` to
regenerate it after editing `generate()` in `bank.py`.

## What every classifier here does

All three models follow the same recipe:

1. compute a **score** for each customer (a number from -inf to +inf, also called the
   margin or log-odds);
2. turn it into a **probability** of default, with `sigmoid(score) = 1 / (1 + e^-score)`;
3. turn the probability into a **decision** with a threshold, 0.5 unless you choose
   otherwise.

They differ only in how the score is computed and how it is fitted. Fitting means
minimising a **loss** on the training rows. Two numbers judge the result on the test rows:

- **accuracy**: how many of the 100 decisions are right. Easy to read, but coarse:
  one customer is one point, so differences of 2-3 points are noise here.
- **log-loss**: the average of `-log(probability given to what actually happened)`.
  It judges the probabilities, not only the decisions, and punishes confident mistakes
  hard. Lower is better; always predicting the base rate scores 0.688.

## Step 1: logistic regression (`logistic.py`)

The score is a straight line: `score = b + w_income * income + w_missed * missed`.
Three numbers make the whole model, and each one can be read directly.

What the script prints:

1. the weights and their odds ratios: one more missed payment multiplies the odds of
   default by 2.64, 10k EUR more income multiplies them by 0.55;
2. a check that `predict_proba` is just `sigmoid(b + X @ w)`;
3. the same fit by hand with Newton's method, matching scikit-learn to 1e-15. It uses
   `g = p - y` and `h = p(1 - p)` per row, exactly the g and h of XGBoost in step 3;
4. test results: **78/100, log-loss 0.485**;
5. L2 regularisation (`C`) shrinking the weights.

**Try:**

- **Move the threshold.** Replace `0.5` in `p_test > 0.5`. Fewer missed defaulters
  costs more false alarms:

  | threshold | correct | defaulters caught (of 43) | false alarms (of 57) |
  | --- | --- | --- | --- |
  | 0.2 | 65 | 41 | 33 |
  | 0.3 | 76 | 37 | 18 |
  | 0.5 | 78 | 27 | 6 |
  | 0.7 | 70 | 15 | 2 |

  The model and its probabilities did not change, only the decision rule. Which
  threshold is "best" depends on what a missed defaulter costs compared with a false
  alarm, not on the model.
- **Regularise.** Section 5 already sweeps `C`: at `C=0.001` the `missed` weight falls
  from 0.97 to 0.07 and accuracy drops to 64/100. Smaller `C` means a simpler, more
  cautious model; too small and it can no longer fit the signal.
- **Drop a feature.** Fit on `X[train][:, [0]]` and score on `X[test][:, [0]]` (income
  only), then the same with `[1]` (missed only). Income alone gets 62/100 (log-loss
  0.614), missed alone 69/100 (0.591), both 78/100 (0.485): each feature adds
  information the other does not have.

## Step 2: gradient boosting with squared error (`toy_gbm.py`)

A different kind of score: a sum of many small trees. Start every customer at the
base rate (0.385), then repeat: fit a depth-2 tree to the **residuals** `y - p` (what
the model still gets wrong), and add a small step of it (`LEARNING_RATE`) to `p`.
Each tree is a few "is income > t?" / "is missed > t?" questions.

This toy treats `y` as a number and minimises squared error, so `p` is fitted
directly instead of a score passed through a sigmoid. Result: **78/100**.

**Try** `LEARNING_RATE` and `N_TREES`:

| `LEARNING_RATE` | `N_TREES` | test correct | train correct (of 400) | range of `p` |
| --- | --- | --- | --- | --- |
| 0.01 | 10 | 57 | 246 | 0.36 to 0.42 |
| 0.01 | 200 | 78 | 303 | 0.09 to 0.84 |
| 0.01 | 2000 | 74 | 328 | -0.05 to 1.17 |
| 0.1 | 200 | 75 | 331 | -0.04 to 1.22 |
| 1.0 | 200 | 62 | 372 | -0.39 to 2.20 |

Three things to see:

- **Too few steps underfit**: after 10 small steps every `p` is still near the base
  rate, and the model predicts "no default" for everyone (57/100).
- **Too many or too big steps overfit**: training accuracy keeps rising (372/400) while
  test accuracy falls (62/100). The trees start fitting noise in the 400 training rows.
- **`p` leaves [0, 1]**: squared error does not know `p` is a probability, so it
  happily predicts -0.39 or 2.20. That is why real boosting for classification works
  on the score and uses log-loss: step 3.

Also try adding `print(np.abs(y[train] - p[train]).mean())` inside the loop, after the
`p = p + ...` line, to watch the residuals shrink tree by tree.

## Step 3: the same skeleton with XGBoost's math (`toy_xgb.py`)

Same `grow()` + loop as step 2, with what the XGBoost paper adds:

- the trees build up the **score**, and `sigmoid(score)` is the probability, as in step 1;
- the loss is **log-loss**; each tree is fitted from two numbers per row,
  `g = p - y` and `h = p(1 - p)`, the same g and h as the Newton fit in step 1;
- **regularisation knobs**: `lam` (shrinks leaf values), `gamma` (minimum gain to keep
  a split), `min_child` (minimum sum of h in a leaf), `eta` (step size), `depth`.

Default settings (library defaults, depth 2, 50 trees): **75/100, log-loss 0.542**.

**Try** `fit(...)` with other arguments (the `__main__` block calls `fit()`):

| setting | test correct | test log-loss | train log-loss |
| --- | --- | --- | --- |
| default (`eta=0.3`, 50 trees, depth 2) | 75 | 0.542 | 0.438 |
| `n_trees=10` | 76 | 0.521 | 0.504 |
| `n_trees=500` | 66 | 0.684 | 0.297 |
| `eta=1.0, n_trees=200, depth=4` | 63 | 0.947 | 0.149 |
| `lam=0, min_child=0, depth=6, n_trees=300` | 61 | 3.011 | 0.062 |
| `depth=1` | 78 | 0.516 | 0.494 |

- **Overfitting shows in the gap** between train and test log-loss. With no
  regularisation and deep trees, train log-loss is almost 0 and test log-loss is 3.0:
  the model is very confident and often wrong. `lam` and `min_child` are what stop this.
- **Depth 1 wins here.** Trees of depth 1 (one question each) add up to a score that is
  a sum of separate effects of income and missed, with no interactions. That is almost
  exactly the shape of the true model in `bank.py`, so the simplest booster does best.

## The three models side by side

| | logistic regression | toy_gbm | toy_xgb |
| --- | --- | --- | --- |
| score | `b + w · x` | sum of trees, on `p` directly | sum of trees, on the log-odds |
| loss | log-loss | squared error | log-loss |
| fitting | Newton steps on 3 numbers | each tree fits the residuals | each tree is a Newton step from g, h |
| main knobs | `C` | learning rate, trees, depth | `eta`, trees, depth, `lam`, `gamma`, `min_child` |
| test correct | 78 | 78 | 75 |
| test log-loss | **0.485** | 0.533 | 0.542 |

**On this data the straight line is the best model.** That is not a failure of
boosting: the data was generated by a logistic model, so a line is the right shape.
Trees earn their keep when the signal is not linear in the log-odds (thresholds,
interactions, U-shapes), and they find that shape without being told. The habit to
take away: fit the simple model first, and make the complex one beat it on the
test set.

## Step 4: check the toy against the real library

`compare_xgboost.py` trains the `xgboost` library with `tree_method="exact"` and the
same knobs as `toy_xgb.py`, and compares the scores on all 500 customers: they agree
to about 1e-6 on 5 of the 6 configurations. The sixth (no regularisation) matches on
the training rows but sends a few test customers to different leaves, because of
equal-gain ties (finding 3 below). `debug_one_tree.py N` prints the library's N-th tree
with its `gain` and `cover` (sum of h) on each node, next to the toy's output.

### From toy_gbm to XGBoost

`toy_gbm.py` already *is* XGBoost for one special case. With squared loss,
`g = p - y = -e` (minus the residual) and `h = 1`, so:

- `sse(L) + sse(R) = sum(e^2) - G_L^2/n_L - G_R^2/n_R`, so minimising it is
  maximising `G_L^2/H_L + G_R^2/H_R`: the paper's Eq. (7) with `lambda = 0`.
- the leaf `e.mean()` is `-G/H`: the paper's Eq. (5) with `lambda = 0`.

So `toy_gbm.py` = XGBoost with squared error, `lambda=0`, `gamma=0`,
`min_child_weight=0`, `eta=0.01`, `max_depth=2`. What the paper adds:

| Knob | Paper | Effect | In toy_xgb.py |
| --- | --- | --- | --- |
| any convex loss | Sec. 2.2, second-order Taylor | needs only `g_i`, `h_i` per row | `g, h = q - y, q*(1-q)` (log-loss) |
| `lambda` (L2 on leaf weights) | Eq. (2), (5) | shrinks each leaf toward 0; small nodes shrink most | `-G / (H + lam)` |
| `gamma` (min split loss) | Eq. (2), (7) | a split must gain more than gamma, pruned bottom-up | `best <= gamma` |
| `min_child_weight` | not in the paper | a child needs `sum(h) >= value`; with log-loss h = p(1-p), so confident nodes weigh little | `HL >= min_child` |
| `eta` | Sec. 2.3 | shrinkage of each tree | `m + eta * grow(...)` |
| exact greedy split | Alg. 1 | sort once per feature, cumulative sums of g and h | `np.cumsum` |
| `colsample_*`, `subsample` | Sec. 2.3 | random features / rows per tree | not implemented |
| missing values | Alg. 3 | learns a default direction per split | not implemented |
| `hist` / `approx` | Alg. 2, Sec. 3.3 | candidate thresholds from (weighted) quantiles | not implemented |

### What the comparison taught (verified, not from docs)

1. **The library's `gamma` is 2x the paper's gamma.** Eq. (7) has a factor 1/2;
   the library's gain does not. The `gain=` numbers in `get_dump(with_stats=True)`
   are on the library's scale, so to set `gamma`, read the gains of the splits you
   want to kill in the dump and pick a value just above them.
2. **Thresholds are float32 midpoints.** The split is `x < (a + b)/2` computed in
   float32. A test customer whose value sits exactly on a midpoint can go the
   other way in a float64 reimplementation.
3. **Equal-gain ties are broken arbitrarily.** With `lambda=0, min_child_weight=0`
   trees split nodes weighing 0.2, where two different rules separate the
   training rows identically. Same training fit, different test predictions.
   `min_child_weight` and `lambda` remove these degenerate splits.
4. **The library default is not the paper's exact algorithm:** `tree_method`
   defaults to `hist`. `compare_xgboost.py` forces `exact`, and sets
   `base_score` so both start from the same intercept.
